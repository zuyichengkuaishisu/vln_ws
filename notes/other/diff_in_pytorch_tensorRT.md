# 核心笔记：PyTorch vs TensorRT

## 1. 一句话结论
PyTorch 是通用深度学习框架，核心价值在于训练、调试和快速迭代。

TensorRT 是 NVIDIA 的高性能推理引擎，核心价值在于把训练好的模型做部署级优化，让推理更快、更省资源。

## 2. 核心定位
### PyTorch
- 面向模型训练、实验和原型开发
- 支持动态计算图，灵活性高，便于调试
- 既能跑 CPU，也能跑 GPU
- 适合研发阶段

### TensorRT
- 面向模型部署和高性能推理
- 不负责训练，重点是推理优化
- 更偏向静态、编译式执行
- 适合生产环境

## 3. 通俗类比
PyTorch ≈ 源代码 / 解释执行环境

- 改起来方便
- 调试方便
- 灵活但运行时开销更大

TensorRT ≈ 编译优化后的可执行文件

- 提前把图和算子做优化
- 运行时少做动态决策
- 灵活性较低，但执行效率更高

## 4. 关键差异对比
| 维度 | PyTorch | TensorRT |
|---|---|---|
| 主要用途 | 训练、调试、原型开发 | 推理部署、性能优化 |
| 是否支持训练 | 支持 | 不支持 |
| 计算图特点 | 动态图，更灵活 | 更偏静态图，更利于优化 |
| 易用性 | 高，开发体验好 | 部署链路更复杂 |
| 性能重点 | 通用执行能力 | 极致推理速度与吞吐 |
| 典型阶段 | 研发阶段 | 生产部署阶段 |

## 5. PyTorch 如何使用 GPU
PyTorch 本身并不是推理加速器，它主要是通过 CUDA 调用 GPU 来执行张量计算。

常见方式：

```python
model = model.to("cuda")
x = x.to("cuda")
```

这类方式的本质是把模型和数据放到 GPU 上运行，属于通用 GPU 加速。

特点是：
- 使用简单
- 适合训练和调试
- 运行时仍存在较多通用框架开销

## 6. TensorRT 为什么更快
TensorRT 的优势不在于“能用 GPU”，而在于“更深度地榨干 GPU 推理性能”。

常见优化手段包括：

### 层融合（Layer Fusion）
把多个相邻算子合并，减少中间张量读写，降低显存带宽开销。

### 低精度优化
支持 FP16、INT8 等低精度推理，在精度可接受的前提下显著提升吞吐量和延迟表现。

### 内核自动调优（Kernel Auto-Tuning）
针对具体的 NVIDIA GPU 架构，自动选择更合适的底层实现。

### 内存与执行优化
尽量减少不必要的内存分配和数据搬运，让执行路径更紧凑。

## 7. 典型工作流
### 研发阶段
使用 PyTorch 完成：
- 模型设计
- 训练
- 调试
- 验证效果

### 部署阶段
一般流程为：

`PyTorch 模型 -> 导出 ONNX -> TensorRT 编译优化 -> 生成引擎 -> 在线推理`

## 8. 容易混淆的点
### 1. PyTorch 也能用 GPU，为什么还要 TensorRT？
因为“能在 GPU 上运行”不等于“已经做了部署级极致优化”。

PyTorch 更像通用框架执行，TensorRT 更像专门为推理场景做过编译和压榨优化的执行引擎。

### 2. TensorRT 生成的 `.engine` 文件能单独运行吗？
不能完全脱离环境独立运行。

它通常需要 TensorRT Runtime 来加载和执行，类似“编译好的程序仍依赖对应运行时环境”。

### 3. TensorRT 一定比 PyTorch 快吗？
大多数部署场景下通常更快，但是否明显更快取决于：
- 模型结构
- 算子是否被良好支持
- 是否启用 FP16 / INT8
- GPU 硬件型号
- 实际 batch size 和部署方式

## 9. 补充理解
PyTorch 2.x 中的 `torch.compile` 也是重要的原生优化路径。

它在保留较好易用性的同时，也能对执行过程进行一定程度的编译优化。可以把它理解为：

- PyTorch 体系内的性能增强方案
- 但通常不等同于 TensorRT 这种面向生产推理的专项部署优化工具

## 10. 最终记忆版
如果只记一句话：

`PyTorch 负责把模型做出来，TensorRT 负责把模型跑得更快。`
